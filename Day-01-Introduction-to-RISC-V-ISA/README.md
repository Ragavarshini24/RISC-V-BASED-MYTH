## 3. Introduction to RISC-V ISA

RISC-V stands for Reduced Instruction Set Computer – Five.

An Instruction Set Architecture acts as an interface between software and processor hardware. It defines the instructions, registers, and operations supported by the processor.

The processor executes instructions represented in binary format (0s and 1s).

### Software and Hardware Interaction

A computer program written in a high-level language cannot be directly understood by the processor. It must be translated into machine-level instructions.

The general flow is:

Application Software → System Software → Hardware

System software helps convert application programs into executable instructions.

## 4. Understanding the Compiler Toolchain

A compiler toolchain contains different software tools that help transform a program into machine-executable code.

### Compiler

A compiler translates a high-level language program, such as C, into assembly or another lower-level representation.

### Assembler

An assembler converts assembly-language instructions into machine-code instructions represented in binary.

### Operating System

The operating system provides services such as:
- Input/output operations.
- Memory management.
- Execution of programs.
- Low-level system functions.

## 5. Application-to-Hardware Flow

The execution process involves multiple stages:

1. An application program is written in a high-level language.
2. The compiler translates the program into lower-level instructions.
3. The assembler converts assembly instructions into machine code.
4. The executable program is loaded for execution.
5. The processor executes the instructions.

### Step 2 : Cross Compilation for RISC-V

The source program was compiled using the RISC-V GCC cross compiler to generate executable files for the RV64I instruction set.

**Compilation with O1 optimization:**

```bash
riscv64-unknown-elf-gcc -O1 -mabi=lp64 -march=rv64i -o sum1ton.o sum1ton.c
```

**Compilation with Ofast optimization:**

```bash
riscv64-unknown-elf-gcc -Ofast -mabi=lp64 -march=rv64i -o sum1ton.o sum1ton.c
```

Two executable files were generated with different optimization settings. These files can be used to study how compiler optimization affects the generated instructions.

### Step 3 : Analysis of Generated Assembly Code

The `objdump` utility was used to convert the executable files into a readable disassembly format.

**For O1 optimization:**

```bash
riscv64-unknown-elf-objdump -d sum1ton.o | less
```

**For Ofast optimization:**

```bash
riscv64-unknown-elf-objdump -d sum1ton.o | less
```

The output contains RISC-V assembly mnemonics, instruction addresses, and corresponding machine-code representations. This helps in examining the instructions generated by the compiler.

### Step 4 : Execution Through Spike Simulator

**Normal execution:**

```bash
spike pk sum1ton.o
```

**Execution in debugging mode:**

```bash
spike -d pk sum1ton.o
```

Debug mode allows the execution of instructions to be monitored step by step.

### Step 5 : Register Inspection and Debugging

During simulation, the following commands were entered to monitor processor execution.

```text
until pc 0 100b0
reg 0 a0
```

**Description of commands:**

- `until pc 0 100b0` – Continues execution until the program counter reaches the specified address.
- `reg 0 a0` – Displays the current contents of the a0 register of processor 0.

By examining the register contents, we can understand how values are transferred and processed during program execution.

## 6. Lab 02 – Analysis of 64-bit Integer Storage in RISC-V

The RV64 architecture of RISC-V uses 64-bit registers to perform integer operations. Data is represented in binary form, and its meaning depends on whether it is treated as signed or unsigned.

### 6.1 Data Organization in RV64

Computer systems use different data sizes to store information. The commonly used units are:

| Data Type | Storage Capacity |
|---|---|
| Bit | 1 binary digit |
| Byte | 8 bits |
| Halfword | 2 bytes |
| Word | 4 bytes |
| Doubleword | 8 bytes |

In RV64, a doubleword represents the standard 64-bit data size.

Two important positions in a binary number are:
- **LSB:** The rightmost bit, which has the lowest positional value.
- **MSB:** The leftmost bit, which has the highest positional value and indicates the sign in signed representation.

### 6.2 Representation of Positive and Negative Integers

There are two common ways to interpret binary integer data.

**A. Unsigned Representation**

This format is suitable for storing values that are zero or greater. All available bits are used to represent the magnitude of the number.

The maximum value depends on the number of bits available.

\[
\text{Maximum value}=2^n-1
\]

For RV64:

\[
\text{Range}=0 \text{ to } 2^{64}-1
\]

For example, a 3-bit system can generate eight different binary combinations, representing decimal values from 0 through 7.

If an arithmetic result crosses the maximum representable value, the excess is wrapped around using modulo \(2^{64}\) arithmetic.

**B. Signed Representation Using 2's Complement**

Unlike unsigned representation, signed representation allows a processor to work with negative as well as positive integers.

The sign is identified using the most significant bit. A zero in this position indicates a non-negative value, whereas a one indicates a negative value.

The mathematical limits for signed integers are:

\[
-2^{n-1} \text{ to } 2^{n-1}-1
\]

For a 64-bit signed number:

\[
-2^{63} \text{ to } 2^{63}-1
\]

Negative binary values are obtained through the following procedure:

1. Write the binary form of the corresponding positive number.
2. Perform a bitwise inversion to obtain its 1's complement.
3. Increase the inverted value by one to generate the 2's complement.

Thus, the same 64-bit binary pattern can produce different decimal results depending on whether it is interpreted as signed or unsigned data.

## 7. RISC-V Instruction Set and Its Extensions

The RISC-V architecture uses a modular instruction set. Its extensions provide additional capabilities beyond basic integer processing.

| Instruction Set | Purpose |
|---|---|
| RV64I | Performs basic integer and data-processing operations. |
| RV64M | Adds multiplication and division functionality. |
| RV64F | Enables 32-bit floating-point operations. |
| RV64D | Enables 64-bit floating-point operations. |

### 7.1 Assembly Instructions Studied

Some instructions generated during compilation and assembly-code inspection include:

| Instruction | Operation |
|---|---|
| `LI` | Places a constant value into a register (pseudo-instruction). |
| `LUI` | Loads an immediate value into the upper portion of a register. |
| `ADDI` | Performs addition using an immediate operand. |
| `LD` | Reads a doubleword from memory. |
| `SD` | Writes a doubleword into memory. |
| `JAL` | Transfers control to another location and stores the return address. |
| `RET` | Returns control to the previous calling function. |

These instructions demonstrate the basic operations involved in register manipulation, memory access, arithmetic processing and program execution.
